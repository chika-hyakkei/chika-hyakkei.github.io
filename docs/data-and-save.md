# データ・セーブ仕様

最終確認: 2026-08-04

## 端末内データ

ブラウザの `localStorage` を使う。通常プレイは自動保存される。

| キー | 内容 | 互換性上の注意 |
| --- | --- | --- |
| `chika-hyakkei-run-v3` | 現在の冒険。階層、地図、装備、戦闘、状態異常、商店、遺物など | 冒険中のみ存在する |
| `chika-hyakkei-run-backup-v1` | 現在セーブを書き換える直前の正常な冒険 | 正常終了時は現在セーブと一緒に削除する |
| `chika-hyakkei-run-quarantine-v1` | 読み込めなかった現在セーブの原文 | 自動削除せず、調査・手動復旧用に保持する |
| `chika-hyakkei-meta-v2` | 最高記録、図鑑、熟練度、称号、墓、職業解放 | `v1`から不足値を補完して読む |
| `chika-hyakkei-meta-backup-v1` | Metaを書き換える直前の正常値 | 図鑑・熟練度など恒久記録の1世代バックアップ |
| `chika-hyakkei-meta-quarantine-v1` | 読み込めなかったMetaの原文 | 自動削除せず、調査・手動復旧用に保持する |
| `chika-hyakkei-test-record-v1` | 端末限定の匿名テスト記録 | 自動送信しない |
| `chika-hyakkei-onboarding-v1` | 初回案内5項目の確認済み状態 | Run・Metaと分離し、案内の再表示で安全に初期化できる |
| `chika-hyakkei-locale-v1` | 表示言語 `ja` / `en` | 未設定時は端末言語を判定。対応外・不正値は日本語へ戻す |
| `chika-hyakkei-ranking-player-v1` | ランキング自己ベストを識別する匿名ID | 公開名・メールアドレスではない |
| `chika-hyakkei-ranking-pending-v1` | 送信に失敗した終了記録（最大20件） | 接続可能な次回起動時に同じIDで再送する |

現在RunとMetaは保存前に構造を検査し、直前の正常値をバックアップする。現在値がJSON破損または必須項目不足なら原文を隔離し、正常なバックアップがあれば自動復元する。描画中の例外では、再読込・直前Run・現在Runを隔離してタイトルへ戻る、の選択肢を表示する。

Meta v2の任意項目 `itemDiscovery` はアイテムIDをキー、入手済みを正の値として保持する。旧Metaに項目がなければ空オブジェクトを補完し、バージョン番号は変更しない。Run内の装備には任意の `passive` と `passiveValue` を追加した。旧Run・墓の装備は既存IDから不足する特殊効果だけを補完し、元の名前・能力・価格・個体番号を保持する。未知IDは効果なしのまま保持し、装備の消失やRun破棄は行わない。

`Meta.unlocked` は職業IDの配列で、初期4職業に加えて階層主撃破後の `knight`、20階到達後の `sage`、50階到達後の `samurai`、80階到達後の `alchemist` を保持する。旧Metaは不足する職業を自動追加せず、終了時の現在階を満たしたときだけ既存配列へ追記するため、既存セーブの開始状態を勝手に変えない。

Run v3の任意項目 `supplies` は消耗品ID `c2`、`c4`〜`c10` をキー、個数を非負整数として保持する。旧Runに項目がなければ空の道具袋を補完し、未知IDと不正個数は読み込まない。回復薬 `potions` と爆裂石 `bombs` は従来項目と上限を維持し、道具袋の合計上限5個には含めない。Runの番号は変更しないため、旧版へ戻した場合は追加項目が無視されるだけで既存装備・進行値は保持される。

魔物図鑑の `bestiary` はキーの存在を遭遇済み、値を討伐数として扱う。旧データの正の討伐数はそのまま保持される。戦闘中の苔スライム分裂済み状態はBattleEnemyの任意項目 `traitUsed` に保存し、旧Runでは `false` を補完する。

21階以降で新規生成する通常敵の `kind` は、図鑑添字へ100を足した識別値を使い、25素体・4変異を曖昧なく復元する。100未満の旧 `kind` は従来式で図鑑IDへ変換する。旧戦闘セーブに `catalogId` がなければ、階層と `kind` から読込時に補完する。既存Run・Metaのバージョン番号と図鑑IDは変更しない。

Runの地下依頼 `quest` は `slay`、`descend`、`chests`、テスト専用の `test` を保存する。旧Runに保存された日本語の依頼文は読込時に対応IDへ変換する。変換不能な値は `slay` へ補完する。Run v3の番号は変更せず、旧データのロールバック時も旧版は文字列として保持・読込できる。

Run v3の任意項目 `testPower` はテストモードの強化状態を示す。旧テストRunで項目がない場合は `testMode` を既定値として最強状態を維持し、通常プレイRunは `false` を補完する。テストモードの初期状態開始は `testMode:true,testPower:false` とし、レベル1・初期装備・初期所持品で階層ジャンプできる。通常プレイのセーブ形式・ランキング送信値には影響しない。

Meta v2の任意項目 `deepestSafeFloor` は、通常プレイで最後に倒した階層主の次階を表す奈落降下用の安全地点である。初期値は1、保存範囲は11〜91（未解放時だけ1）とする。旧Metaに項目がない場合は、既存の `bestFloor` から確実に通過済みと推定できる10階区間の次階を補完する。誤った値は範囲内へ丸め、Metaのバージョン番号は変更しない。テストモードの階層主討伐はこの値を更新しない。

Run v3の任意項目 `route` は `normal` または `descent`。旧Runと不正値は `normal` へ補完する。`descent` は奈落降下着地後の冒険を示し、通常と同じ自動保存・Meta更新・墓・熟練度を使う一方、終了時のオンラインランキング送信だけを止める。貸与装備の任意項目 `loaned:true` はRun内だけで使い、売却、アイテム図鑑記録、死亡時の墓候補から除外する。旧Run・墓では値がないため従来どおり通常装備として扱う。

終了Resultの死因、依頼達成値、墓の候補、次の熟練度解放は保存しない。終了直前のRunと更新後Metaから画面表示時に導出し、結果カードを閉じる・再挑戦する・再読込する場合に古い結果が冒険状態へ混ざらないようにする。これらはランキング送信値にも含めない。

## 変更時のルール

保存形式を変える前に、変更前後・既存データへの影響・補完/移行・ロールバック方法を `implementation-log.md` に記録する。既存値はデフォルト補完を優先し、明示的な許可なく削除しない。

## 匿名テスト記録

テスト記録は端末内にだけ残る。含むのはランダムな端末ID、利用日、プレイ/到達/結果の集計、直近結果であり、名前・メール・位置情報は含まない。

## 匿名アクセス集計

Cloudflare Web Analyticsをページ表示時に読み込む。これはゲーム内の端末記録・セーブ・ランキングとは別で、ページビュー、匿名化された訪問集計、参照元、端末・表示性能の傾向をCloudflareダッシュボードで確認するために使う。ゲーム内の名前、プレイ内容、localStorageの値は送信しない。ブラウザの追跡防止設定などにより集計は実数より少なくなることがある。

## オンラインランキング

- 通常ルート（`route:"normal"`）の死亡、中断、帰還、踏破時に自動送信する。テストモードと奈落降下ルートは送信しない。
- 終了記録には冒険終了ごとの `submissionId` を付ける。送信前に端末キューへ保存し、成功後だけキューから除く。
- WorkerとD1は `submissionId` を一意に扱い、通信結果を受け取れず再送した場合も同じ記録を二重登録しない。
- 公開するのは公開名、職業、階層、得点、討伐数、階層主数、結果、日時。
- D1には終了した冒険ごとの記録を保存する。
- 現段階ではクライアント申告値を検証しないカジュアルランキング。厳密な順位保証はしない。
- タイトル画面では、公開名・到達階だけの総合上位3件を自動取得して表示する。

終了後は総合ランキングを自動で開く。送信された今回の行は、Workerが返す記録IDを使って黄色に点滅表示する。週間ランキングは利用者が増えるまで画面・APIとも休止するが、将来の再開に備えてD1の `week_key` は保持する。

WorkerのAPI、テーブル、移行手順は `ranking-api/` を参照する。
